# Test coverage policy

ITAMbox measures line **and** branch coverage of the complete serial test suite
against a PostgreSQL test database that pytest-django creates and migrates from
scratch, and holds three properties in CI:

| Gate | Script | Question it answers |
|---|---|---|
| Global ratchet | `scripts/check_coverage_baseline.py` | Did overall coverage slip below the reviewed baseline? |
| Differential | `scripts/check_diff_coverage.py` | Is the code this change touched actually tested? |
| Run certification | `scripts/check_test_report.py` | Did the suite really run — all of it? |

All three are stdlib-only, fail closed, and treat an unusable measurement as a
failure rather than a pass. Exit code `1` is a policy violation; exit code `2`
means the gate could not produce a trustworthy answer at all.

Coverage proves a line *ran*. It cannot prove the test *asserted* anything
meaningful about it, so these gates are a floor, not a substitute for review.
[Security test expectations](security-test-expectations.md) defines what tests
covering boundary-sensitive behaviour must assert.

## What is measured

The measurement configuration lives in `pyproject.toml`, and the policy it must
match is declared once in `scripts/coverage_policy.py`.

!!! warning "`--cov-config` is mandatory"

    coverage.py looks for its configuration in the **current directory**, and
    `pytest` runs from `itambox/`. Any `--cov` invocation that omits
    `--cov-config=../pyproject.toml` silently ignores the root configuration:
    no branch measurement, and generated migrations and test files counted as
    covered source — which inflates the reported percentage substantially.
    `make coverage` and the CI job pass it; pass it in ad-hoc runs too. The
    gates fail closed on a report produced without it rather than comparing
    incomparable numbers.

The settings the policy pins:

| Setting | Value | Why |
|---|---|---|
| `branch` | `true` | A half-taken conditional is where tenancy and permission regressions hide; line coverage reports it as fully covered. |
| `relative_files` | `true` | Absolute paths are machine-specific and would make a report incomparable between a contributor's run and CI's. |
| `omit` | see below | What is deliberately not measured. |
| `exclude_also` | see below | Individual lines that carry no runtime behaviour. |
| `fail_under` | coarse floor | A blunt backstop for ad-hoc local runs. **Not** the ratchet. |

`verify_measurement_policy` refuses to run any gate when `pyproject.toml` and
`scripts/coverage_policy.py` disagree. Silently adding an `omit` entry would
raise every reported rate without a single test being written, so the two lists
are kept identical by force rather than by convention.

### Excluded paths

Generated code, test code, and process entry points only — never hand-written
application code.

| Pattern | Reason |
|---|---|
| `*/migrations/*` | Generated by `makemigrations`; verified by the migration audit gate instead. |
| `*/tests/*`, `*/tests.py`, `*/conftest.py` | Test code measures the application, not itself. |
| `manage.py`, `core/wsgi.py`, `core/asgi.py`, `itambox/wsgi.py`, `itambox/asgi.py` | Process entry points, exercised by the Docker smoke and deployment jobs. |

### Excluded lines

| Pattern | Reason |
|---|---|
| `if TYPE_CHECKING:` | Import-time-only block; no runtime behaviour. |
| `raise NotImplementedError` | Abstract contract marker; the subclass implementations are measured. |
| `@abstractmethod` | As above. |
| `if __name__ == "__main__":` | Script entry point; the callable body above it is measured. |

Excluded lines are invisible to every percentage, so this list is deliberately
short and the gate ratchets its *effect*: if the total number of excluded lines
grows, the build fails until the growth is reviewed and recorded. `# pragma: no
cover` counts towards that total, which is why it cannot be used to quietly
retire a hard-to-test branch.

## The global ratchet

`scripts/coverage_baseline.json` records the reviewed line rate, branch rate,
excluded-line count, and the totals they were derived from. The baseline is
bound by SHA-256 to the effective policy and to the measuring `coverage.py`
series; changing either invalidates it and forces a reviewed regeneration.

The gate fails when:

- either rate falls more than `0.10` percentage points below the recorded value
  (**regression**);
- either rate rises more than `1.00` percentage point above it (**stale
  baseline**) — unrecorded improvement becomes headroom that later untested code
  can spend, so improvements must be recorded;
- the excluded-line count grows;
- the measured file, statement, or branch count shrinks. A smaller denominator
  can make both rates rise while less production code is measured.

Coverage baselines may only be written under Python 3.12 on Linux, matching the
canonical CI environment. Reading and checking them remains supported on every
development platform. Record a new baseline after an improvement from a clean
Linux/CI-equivalent run:

```bash
make coverage            # measure
make coverage-baseline   # record
```

Recording a genuine *decline* — for example when a well-covered module is
deleted — is possible but never silent:

```bash
python scripts/check_coverage_baseline.py \
  --coverage-json itambox/coverage.json \
  --write-baseline --allow-decline \
  --reason "removed the legacy importer; its 300 covered lines went with it"
```

The reason is written into the baseline next to the rates it replaces, and shows
up in review as a diff of `scripts/coverage_baseline.json`. A decline without
`--allow-decline --reason` is refused.

## Differential coverage

On a ~19k-statement code base a few hundred untested new lines barely move a
global percentage. The differential gate is what actually holds new work to a
high standard: it looks only at the lines a change added or modified and
requires **85%** of them to be covered.

"Covered" here is branch-aware. A changed line counts as covered only when it
was executed **and** is not the origin of an untaken branch. A new `if` whose
`else` never runs is exactly the case plain line coverage reports as 100%.

Lines that are neither executed nor missing (blank lines, comments, and
excluded lines) are not executable and are not counted either way.

### Unmeasured files fail closed

A changed Python file that the coverage run never measured is a failure, not a
pass — an unmeasured file is an unknown. The only exceptions are the documented
patterns in `DIFF_COVERAGE_EXEMPTIONS` (`scripts/coverage_policy.py`), each of
which names the gate that covers that path instead:

| Path | Covered instead by |
|---|---|
| `scripts/*` | The `scripts/tests/*` unittest suites, run separately in CI. |
| `itambox/tests/e2e/*` | The Playwright suite in the `e2e` workflow. |
| `itambox/static/*` | `tsc --noEmit` and ESLint in the `frontend` job. |

Adding an exemption requires a reason and a real alternative gate. "It is hard
to test" is not one.

The repository-tooling suites in the main CI test job are loaded with `unittest
discover`, not a hand-maintained module list. Therefore every new
`scripts/tests/test_*.py` file is included automatically there.

Test code, generated migrations, and process entry points are not exemptions —
they are excluded from "production code" by the same declared policy the global
gate uses.

### Running it locally

```bash
make coverage                              # produces itambox/coverage.json
make coverage-diff                         # against origin/main
make coverage-diff BASE_REF=origin/release-1.0
```

## Run certification and durations

`scripts/check_test_report.py` reads the JUnit XML the run writes and refuses
every shape where a green tick would mislead:

- a missing, unparseable, or empty report — a run that collected nothing must
  never be reported as a run in which nothing broke;
- recorded failures or errors, even though pytest's own exit code already failed
  the job. The redundancy is the point: this is the check that still fires if a
  workflow edit ever swallows an exit code behind `|| true` or
  `continue-on-error`;
- skipped tests above `MAX_SKIPPED_TESTS` (currently `0`). A skip is a test that
  silently did not run. Raising the allowance means naming which tests may skip,
  and why, in review;
- fewer executed tests than `scripts/suite_baseline.json` records. Suite growth
  is free; a deliberate reduction must be recorded on Python 3.12/Linux with
  `--write-baseline --allow-decline --reason "..."`.

Durations are **published, never gated**. Wall-clock on a shared runner is too
noisy to fail a build on, and a flaky timing gate teaches people to ignore
gates. The slowest tests appear in the job summary and the full report is
uploaded, so the cost of the serial suite stays visible.

## Published artifacts

Every CI run uploads `coverage-and-durations-py3.12`, containing:

| File | Contents |
|---|---|
| `coverage.xml` | Cobertura report, for external tooling. |
| `coverage.json` | Per-file line and branch detail; the input both coverage gates read. |
| `junit.xml` | Per-test outcomes and durations. |
| `htmlcov/` | Browsable line-and-branch report. |

They are uploaded when the suite ran, even if it failed: the durations and
partial coverage of a failing run are what you need to act on. If an earlier
step prevented the suite from starting, there is no misleading empty artifact.

Job summaries carry the same numbers inline — global coverage against baseline,
the differential result with the uncovered lines named, and the slowest tests.

## The serial suite is the source of truth

pytest-xdist is installed but deliberately not enabled. The suite is not yet
parallel-safe (shared `MEDIA_ROOT`, `requests-mock` and django-q timing — see
issue #21), and a flaky parallel run is a weaker signal than a slow serial one,
not a stronger one. Every gate here measures the complete serial suite. When #21
proves safe parallel execution, this policy is what the parallel run must
reproduce before it can replace it.

## When a gate fails

| Message | Meaning | Action |
|---|---|---|
| `global coverage regressed against the reviewed baseline` | Coverage fell below the recorded rate. | Add tests. If the decline is genuinely correct, record it with `--allow-decline --reason`. |
| `the coverage baseline is stale` | Coverage improved beyond the drift allowance. | `make coverage-baseline` and commit the diff. |
| `excluded lines grew to N` | New `# pragma: no cover` or excluded-line matches. | Justify each one in review, then record the baseline. |
| `measured ... fell to N` | The coverage denominator shrank. | Restore measurement, or explicitly record a legitimate deletion with `--allow-decline --reason`. |
| `differential coverage X% is below the target` | New or changed lines are untested, or a new conditional is only half-tested. | Cover the listed lines. |
| `changed production file(s) the coverage run never measured` | A changed file was outside the measured tree. | Bring it under the pytest run, or add a reasoned exemption. |
| `measurement policy mismatch` | `pyproject.toml` and `scripts/coverage_policy.py` disagree. | Change both in the same reviewed commit. |
| `baseline policy_sha256 does not match` | The policy changed without regenerating the baseline. | Regenerate in the same change. |
| `skipped test(s) exceed the allowance` | A test silently did not run. | Fix the condition, delete the test, or raise `MAX_SKIPPED_TESTS` with a stated reason. |
| `test(s) ran, below the reviewed baseline` | Part of the suite no longer executed. | Restore collection, or explicitly record deliberate test deletion in `suite_baseline.json`. |
